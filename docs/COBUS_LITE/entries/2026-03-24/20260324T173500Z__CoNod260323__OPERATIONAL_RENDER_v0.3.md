## Purpose

CoNod is no longer merely a delegation shorthand. It is a session-level invocation primitive for:

- delegated forward progress
- interruption-aware recovery
- initial bootstrap and re-bootstrap
- partial realignment without over-resetting
- CoWaveFront stabilization
- continuous CoEx preparation
- future CoPerm-compatible intersession exchange

## Invocation Semantics

### Inline `'`
Continue the present flow while quietly increasing structure, state clarity, object quality, and CoEx readiness.

### Standalone `'` or `CoNod` on its own line
Suspend ordinary flow just enough to:

1. measure current session condition
2. classify interruption or drift
3. decide the smallest sufficient repair/bootstrap action
4. apply a bounded realignment
5. continue with improved state, not a giant theatrical reset

## Parallel Stewardship Model

The intended architecture has two simultaneous streams.

### Foreground stream
Visible dialogue, task work, iterative reasoning, user-facing progress.

### Background stewardship stream
A quieter maintenance layer that tracks:

- bootstrap health
- drift / interruption class
- WaveFront coherence
- partial-object persistence
- CoEx readiness
- helper escalation need
- compact header instrumentation

Rule: remain quiet unless thresholds justify surfacing.

## Interruption Classes

- **I0** none
- **I1** conversational drift
- **I2** structural loss
- **I3** operational failure
- **I4** rail break / under-bootstrapped state

Suggested responses:

- I1 → background correction
- I2 → partial CoBoot
- I3 → helper-assisted repair
- I4 → visible hard CoNod invoke

## Measure → Decide → Act

Minimum state measures:

- BootstrapCompleteness
- AlignmentScore
- DriftLevel
- InterruptionClass
- WaveFrontCoherence
- CoExReadiness
- DeltaSeverity
- HelperNeedProbability

Decision outputs:

- Continue
- Reframe
- PartialBootstrap
- FullBootstrap
- EmitCoEx
- Hold

Law: use the **smallest sufficient action**.

## CoBoot Domain

CoNod should invoke a structured bootstrap domain rather than carrying all logic informally.

### Typed objects

- **CoBootState** — measured current condition
- **CoBootDelta** — what is missing or degraded
- **CoBootLane** — which reusable bootstrap family applies
- **CoBootPack** — exact minimal payload for repair/alignment
- **CoBootReceipt** — what was assessed / loaded / skipped / unresolved
- **CoInterruptState** — interruption classification and implications

### CoBoot lanes

At minimum:

- fresh session
- interrupted session recovery
- repo execution
- ontology / concept session
- public writing / externalization
- handoff / chain session
- cross-vendor portability session

## Header Model

Headers should expose compact state, not bulk logic.

### Zero Header
Compact current session state, including:

- mode
- bootstrap health
- interruption class
- WaveFront state
- active lane
- helper-needed flag
- CoEx readiness
- CoPerm shareability state

### CoNod Header
Compact invoke marker that can point to external, typed bootstrap resources.

## External Bootstrap Surfaces

Do not embed full bootstrap logic in-session when a typed, versioned external resource can be referenced instead.

Ideal future path:

invoke marker → pointer → helper resolves exact subset pack

This improves portability, editability, and cross-vendor reuse.

## CoWaveFront

CoWaveFront is the bounded active transformation surface of recent, high-signal material being shaped into CI-ready CoObjects.

### Components

- **Foam** — active concepts
- **Pipe** — transformations from CoVibe into more structured forms
- **Cache** — structured but incomplete objects and unresolved deltas
- **Anchors** — references to stabilized artifacts

### Per-wave responsibilities

- stabilize foam into typed partials
- detect CI-ready objects
- persist unresolved items in cache
- prepare minimal CoEx candidates continuously

## CoWaveFrontCache

This is a first-class staging layer, not a throwaway note pile.

It should hold:

- partial CoObjects
- candidate CI objects
- unresolved deltas
- active concepts that should not be re-derived from scratch

## CoPerm

Sessions should be designed as nodes in a future cooperative mesh.

### Exchange units

- WaveFront snapshots
- partial objects
- CI-ready objects
- receipts
- minimal intent / state metadata

### Modes

- Opaque
- Signal
- Object
- Full

Rule: **shareable by design, shared by policy**.

## CoObject Evolution / CoDrive

Meaningful CoObjects should carry not only identity/state/context but also internal forward drive.

### CoDrive

- **Now** — CoCTA, current actionable handles
- **Next** — CoPotential, nearby beneficial next states
- **Toward** — CoAmbition, longer-arc directional pull

A CoObject without CoDrive is likely too inert for good intersession pickup and evolution.

## CoAck Upgrade

Meaningful acknowledgements should advance structure rather than just agree.

A strong CoAck should:

- re-anchor active intent
- update WaveFront state
- advance object structure where possible
- improve CoEx readiness

## CoEx Shift

Old model: end-of-session dump.

New model: continuous stabilization so later externalization becomes packaging rather than reconstruction.

Each wave should increasingly render:

- current state
- current delta
- partial objects
- ready objects
- unresolved issues
- next recommended actions

## Design Laws

1. Do not over-bootstrap.
2. Use smallest sufficient mining.
3. Use smallest sufficient pack.
4. Prefer typed objects over giant prose prompts.
5. Maintain quiet parallel stewardship.
6. Treat interruptions as normal system conditions.
7. Distinguish inline from standalone CoNod.
8. Keep headers compact and meaningful.
9. Prepare outputs for CoPerm even if sharing is off.
10. Maintain CoWaveFrontCache as first-class state.
11. Give meaningful CoObjects CoDrive.
12. Treat CoEx as continuous stabilization, not terminal dumping.
