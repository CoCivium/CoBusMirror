STATUS: non-authoritative seed

## INTENT
Define how CoObjects are created, evolve, gain importance, or decay over time.

## STAGES

### 1. CREATION
- input becomes CoObject
- assigned:
  - id
  - type
  - source
  - initial dimensions
  - quarantine grade

### 2. STABILIZATION
- filtered (CoFilter)
- placed in scope (CoScope)
- linked via initial overlaps

### 3. EVOLUTION
- dimensions updated via:
  - new overlaps
  - repeated occurrence
  - external validation
- may split or merge with other CoObjects

### 4. PROMOTION
Eligible when:
- high overlap with trusted clusters
- increasing confidence
- cross-session convergence

Promotion paths:
- exploratory → creative cloud
- exploratory → canonical candidate
- creative → structured concept

### 5. ACTION (OPTIONAL)
If EXECUTION_HITCHED context:
- may trigger:
  - automation
  - publication
  - policy consideration

### 6. DECAY / ARCHIVE

Occurs when:
- low overlap
- low reuse
- outdated context
- superseded by stronger objects

Decay actions:
- reduce visibility (via CoScope)
- archive (retain but deprioritize)
- eventual pruning (optional)

## KEY PRINCIPLES

- objects are dynamic, not static
- promotion is earned, not assigned
- decay is necessary to prevent overload
- overlap drives evolution more than origin

## FAILURE MODES PREVENTED

- accumulation of dead concepts
- premature canonization
- loss of weak but valuable signals

## RELATION TO SYSTEM

- CoFilter + CoQuarantine → intake
- CoScope → visibility
- CoObjectOverlap → evolution
- Hitch States → action authority

## SUGGESTION TO COPRIME

Adopt lifecycle as:
- default behavior for all CoObjects
- basis for CME evolution dynamics

## BOUNDARY

Conceptual lifecycle only.
No enforcement implied.
